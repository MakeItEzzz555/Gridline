# Building Envelope Performance

Coordinate continuous performance layers and buildable interfaces; source product and climate data rather than inventing it.

## Preflight

- Climate/location, indoor design conditions, exposure, orientation, assembly geometry and structural support.
- Target thermal/air/water/acoustic/fire performance, product data, applicable standards and consultant inputs.

Keep verified facts, project assumptions, design options, and unresolved questions visibly separate. If a required input is absent, record it as `UNKNOWN` rather than inventing it.

## Workflow

1. Draw continuity diagrams for water, air, vapor and thermal control layers through representative interfaces.
2. Review openings, parapets, balconies, roofs, foundations and material transitions for drainage, movement, thermal bridges and sealant/flashing continuity.
3. Evaluate preliminary thermal/moisture risks using verified material properties and climate assumptions; request specialist analysis when needed.
4. Translate the strategy into outline details, performance requirements and mock-up/testing questions.

## Deliverables

- Envelope control-layer diagrams
- Interface/detail risk register
- Performance requirement matrix
- Testing/mock-up and consultant questions

## Verification

- Control layers remain continuous across sections/details and product properties are sourced.
- Condensation/U-value/acoustic/fire statements identify method, inputs and limitations.

For file/model changes, compare the result against a pre-change baseline and report changed items, skipped items, failures, and checks actually run.

## Professional boundaries

- Do not certify facade, waterproofing, hygrothermal, fire or structural performance.
- Do not fabricate manufacturer values or substitute generic details for project-specific engineering.

If a live CAD/BIM/GIS/analysis tool or MCP integration is available, inspect the current document/model and tool version before write operations. Prefer read-only inspection, dry runs, bounded samples, new output paths, and native undo/transaction mechanisms. Never claim a model or drawing was changed unless the tool confirms it.

If the native application is unavailable, produce a reproducible plan, script, structured data, SVG/DXF artifact, or exact in-application procedure instead of pretending to have operated the software.
