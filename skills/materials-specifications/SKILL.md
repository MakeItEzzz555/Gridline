# Materials & Specifications

Connect design intent to measurable performance, installation, coordination and maintenance requirements.

## Preflight

- Project stage, location/exposure, assembly/function, design intent, durability/maintenance goals, fire/acoustic/thermal/moisture requirements, budget and procurement constraints.
- Office/master specification system and product/manufacturer information when available.

Keep verified facts, project assumptions, design options, and unresolved questions visibly separate. If a required input is absent, record it as `UNKNOWN` rather than inventing it.

## Workflow

1. Define required performance before naming products; separate basis-of-design, approved equal and performance-only requirements.
2. Compare materials on technical performance, durability, maintenance, embodied impact, availability, lead time, install interfaces and replacement strategy.
3. Draft concise specification clauses or schedules with scope, products/performance and execution/quality-control headings.
4. Coordinate specifications against drawings, schedules and details; track substitutions and deviations explicitly.

## Deliverables

- Material/finish option matrix
- Outline or three-part specification draft
- Finish/product schedule
- Substitution/deviation register

## Verification

- Product values and standards are source-linked and edition-specific.
- Drawings, schedules and specifications use consistent material/assembly names and performance requirements.

For file/model changes, compare the result against a pre-change baseline and report changed items, skipped items, failures, and checks actually run.

## Professional boundaries

- Do not reproduce copyrighted specification libraries or standards verbatim beyond allowed excerpts.
- Do not invent certifications, test results, warranties, availability or code approvals.

If a live CAD/BIM/GIS/analysis tool or MCP integration is available, inspect the current document/model and tool version before write operations. Prefer read-only inspection, dry runs, bounded samples, new output paths, and native undo/transaction mechanisms. Never claim a model or drawing was changed unless the tool confirms it.

If the native application is unavailable, produce a reproducible plan, script, structured data, SVG/DXF artifact, or exact in-application procedure instead of pretending to have operated the software.
